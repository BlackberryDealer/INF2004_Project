# RAM comparison: baseline vs packed

Generated by `tools/ram_report.sh` (spec B4.5). The baseline image
stores the same information in natural types; the packed image uses the
`tools/layout.csv` fields. Sections 2 and 3 are the storage comparison;
the `.text` row of section 1 is informational only, because the packed
build also carries the encode/decode code.

> **Sections 1-3 are the Week 11 Buddy 4 comparison** (pre-packing
> baseline `05a20af` vs the Phase 4 packed IMU). They are kept as
> measured then. Later team images are measured in sections 5-6, and the
> final submitted course image is measured in section 7.

## 4. Change Requirement 2 (lift-stop, 2026-11-12)

Not part of the baseline-vs-packed comparison above (the baseline ELF is the
pre-packing commit). Measured separately on the car image
(`make NET=lwip MQTT=1`): `main` `14c3dc1` vs the lift-stop change.

| Section | Before B | After B | Delta |
|---------|---------:|--------:|------:|
| .data | 340 | 256 | -84 |
| .bss | 99508 | 99464 | -44 |
| .text | 388332 | 387280 | -1052 |

Removed: `g_imu_impact_seq` (1 B, the ISR byte SH_IMU), `g_imu_isr_us`,
`g_imu_int1_glitches` and the INT1 diagnosis buffers. In PRV_IMU_A the 9 bits
of IMPACT_HOLD + IMPACT_SEQ became the 3-bit LIFT_CNT inside the same word.
Details: `docs/change_requirement_2_lift_stop.md`.

## 7. Final submitted course image (28 Nov 2026)

Final course image built with `testing/run-demo.sh course`
(`make SMP=0 NET=lwip MQTT=1`, Pico SDK 2.3.0, `arm-none-eabi-gcc 15.2.1`):
`mtk3pico_smp0_usb_cdc_wifi_lwip_mqtt.elf` / `.uf2` (UF2 SHA-256
`072aa8b78f9cf6e817f94f259859f5730f6574644a392e159091b42d580a09a9`).
This is the exact binary demonstrated on the car on 25 Nov (`f4e94ad`) and
reproduced byte-for-byte after the unit-constant (`ee23a2e`) and BARR-C:2018
(`6899aa0`) merges; no firmware source file has changed since `6899aa0`.

### Section sizes

| Image | Profile / toolchain | .data B | .bss B | RAM B | .text B |
|---|---|---:|---:|---:|---:|
| `main` `ae78cf5` (before follow-up, section 5) | `SMP=1`, SDK 2.2.0 / gcc 13.2.1 | 256 | 99464 | 99720 | 386548 |
| `tribunal1-packing` `2032fb7` (18 Nov, section 6) | `SMP=1`, SDK 2.2.0 / gcc 13.2.1 | 260 | 97908 | 98168 | 391464 |
| Final course image (`f4e94ad` / `6899aa0`, `size -A`) | `SMP=0`, SDK 2.3.0 / gcc 15.2.1 | 252 | 93828 | 94272* | 384920 |
| Final course image (`f4e94ad` / `6899aa0`, Berkeley `size`) | `SMP=0`, SDK 2.3.0 / gcc 15.2.1 | 252 | 94020 | 94272 | 385632 |

\*`arm-none-eabi-size -A` reports the SRAM `vector` section (`192 B`)
separately from `.bss` (`93828 B`), giving `252 + 93828 + 192 = 94272 B`
total static SRAM (identical to Berkeley `arm-none-eabi-size`, which groups
`vector` into `bss = 94020 B` and `boot2` `256 B` + `.time_critical.tinyusb`
`456 B` into `text = 385632 B`).

The `-3896 B` RAM change from `2032fb7` (`98168 B`) to the final course
image (`94272 B`) comes primarily from switching to the single-core
(`SMP=0`) course build profile (removing Core 1 kernel/idle/interrupt
stacks) and the Pico SDK 2.3.0 / gcc 15.2.1 toolchain rather than further
application packing beyond section 6. The only post-18 Nov application
state additions are `g_imu_prv_r` (`4 B`, IMU calibration-retry state in
`f4e94ad`) and `g_obs_prv_e` (`4 B`).
